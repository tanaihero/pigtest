# Skill 5: 变更记录规范 (Changelog Record)

**触发条件 (When to use):** 当完成了一个新需求的代码编写、修复了一个 Bug，或进行了一次重构之后（在最终回复 tdx 任务完成之前强制执行）。

**执行标准 (Standards):**
1. **记录路径**：在 `.harness/changes/` 目录下生成或更新日志文件。
2. **命名规范**：文件命名为 `change_YYYYMMDD_功能简述.md`（例如：`change_20231024_add_order_module.md`）。
3. **记录内容**：必须包含以下模块：
    - **需求/问题描述**：本次修改解决了什么问题。
    - **涉及微服务/文件**：修改了哪些模块（如 `pig-upms-order`，修改了前端哪些视图）。
    - **数据库变更**：是否新增了表或字段。
    - **API 变更**：新增或修改了哪些 RESTful 接口。
    - **遗留风险 (可选)**：如果为了实现需求做了某些妥协，记录于此。
